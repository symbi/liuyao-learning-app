# 课堂案例

本目录保存从课程中拆分出来的单个课堂案例。理论课和案例课都可以有独立案例；每一课使用自己的子目录：

```text
materials/class-cases/
├── README.md
├── lesson-05/
│   ├── case-001.json
│   └── case-002.json
├── lesson-15/
│   ├── case-001.json
│   └── ...
├── lesson-15/
│   ├── case-001.json
│   └── ...
├── lesson-18/
│   ├── case-001.json
│   └── case-002.json
└── ...
```

每条案例记录只需要：

- `recordType`: 程序识别，固定为 `class-case`
- `id`: 程序生成的案例 ID
- `category`: 在 HTML 里选择的 Category
- `tagOrRealQuestion`: 可选文字，写 tag 或当事人真正的问题
- `casting`: 可选卦盘快照，有可靠资料才保存
- `teacherAnalysis`: 根据课堂资料整理的老师分析摘要和结论；ASR 原文留在 Private raw，不整段复制

课次由所在文件夹 `lesson-XX` 确定，不需要再让用户重复填写。Category 不作为目录名，不需要建立分类子文件夹。

## 和课程笔记、ASR 转录的对应

同一课的三份资料使用相同课次编号：

- Private raw 原始 ASR：`liuyao-learning-raw/lessons/lesson-XX/transcript-asr-raw.txt`
- Public Learning 该课总结：`docs/lessons/lesson-XX-notes-*.md`
- Public Learning 单独案例：本目录下的 `lesson-XX/case-*.json`

整理某一课时，应自动按课次编号读取这三处资料，把案例对应到该课总结中，并添加案例链接。ASR 只是可能有误的参考，不得将听写错误直接当作老师定论；不确定的地方标注待核对。

课程笔记提到但没有足够资料独立复原的内容，可以继续作为该课的「案例线索」，不必强行建立完整案例文件。


## HTML 保存案例后的课程回查流程

用户今后会从 HTML 页面保存具体卦例。整理或分析这些记录时，不能只按 Category 猜课程，而应主动用卦盘信息回查课堂资料：

1. 读取案例 JSON 中的卦盘快照、问题、Category 和备注。
2. 优先按卦名、上下卦、世应、六亲、纳甲地支、动爻、变爻及日月信息，在对应课程笔记和案例目录中寻找候选。
3. 再回到 Private raw 的原始录音/ASR，核对老师讲解的原始上下文和段落/时间戳。
4. 在案例记录中关联 `lessonId`、课程笔记路径、原始来源仓库/路径及可用的转录定位。
5. 只有卦盘和问事背景都能支持同一案例时才标记 `verified`；相似但不能确认的标记 `needs_review` 并说明理由；找不到就明确记为未找到。
6. 不得因卦象相似就强行对应；不得把 ASR 误识、AI 推断或用户后续个人分析写成老师原话。

建议的匹配状态：
- `verified`：确认是课堂讲解的同一个案例，且来源位置已记录。
- `needs_review`：疑似匹配或关键信息不完整，等待原音/卦盘核对。
- `not_found`：现有课程资料未找到对应案例。
- `disputed`：不同来源之间存在需要保留的差异。

案例链接关系建议保持为：HTML 案例 → 对应课程笔记 → Private raw 原始转录/录音位置 → 老师讲解摘要。课程笔记保留整堂课脉络，单个案例仍独立保存。
