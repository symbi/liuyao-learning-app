# 开源项目、古籍与参考资料的调查计划

## 目标

为六爻网页建立一份可检索、可审计的参考资料目录。目标不是把网上找到的一切 PDF 或代码都复制进仓库，而是找到能帮助核实历法/排盘规则的来源，并清楚区分课程体系、外部资料和模型推断。

## 1. 资料来源分层

| 类型 | 用途 | 处理方式 |
|---|---|---|
| 课程原始材料 | 确认老师实际讲法和例子 | 保存于 Private raw；只在需要时读取相关课次 |
| 自行整理的课程笔记 | 快速索引课程内容 | 检查后放入 Public；保留课次/时间戳/原始路径 |
| 开源代码仓库 | 比较算法实现、测试夹具、数据结构 | 先检查源码、测试、许可证、活跃度与已知限制；不把 README 的声称当作正确性证明 |
| 历法/万年历网站 | 交叉核对指定日期/节气 | 记录网址、查询日期、使用的口径；运行时不要依赖网站 |
| 古籍原作/扫描 PDF | 研究传统术语或规则出处 | 记录书名、作者/编者、版本、出版年份、网址、页码和版权状态；不因“古籍”二字就公开复制扫描文件 |
| 现代注释、翻译、校勘本 | 帮助理解古文 | 视为可能受版权保护的现代作品；优先存书目、合法链接和自写摘要 |
| AI 整理/推断 | 帮助发现关键词、形成候选规则 | 一律标成 AI 辅助/待核实，不能代替课程证据或独立测试 |

## 2. 当前可优先评估的公开项目

### 历法
- `6tail/lunar-typescript`：<https://github.com/6tail/lunar-typescript>。TypeScript/JavaScript 项目，README 声明支持公历、农历、干支、节气等功能并采用 MIT 许可证。适合作为前端历法库候选；仍须验证换界口径、时区和边界日期。
- `6tail/lunar-javascript`：<https://github.com/6tail/lunar-javascript>。同生态 JavaScript 实现，适合作为 API/结果对照。无需把它和 TypeScript 版本一起打包。

### 六爻规则/测试参考
- `yaomancy/liuyao-engine`：<https://github.com/yaomancy/liuyao-engine>。README 声明 Apache-2.0，并提供四柱、纳甲、六亲、世应等结构化结果和测试说明。它是 Python 引擎，可用于参考数据结构、测试方法和候选规则；不能未经审查就认定所有规则都符合本课程。
- `1eakkkk/liuyao-tool`：<https://github.com/1eakkkk/liuyao-tool>。README 描述了 Vite/JavaScript 静态前端、起卦与排盘，可用于观察页面信息架构和用户流程。复制代码或素材前必须核实当前 LICENSE 和各素材来源；优先只借鉴设计思路。
- `SmallTeddyGames/divination-liuyao`：<https://github.com/SmallTeddyGames/divination-liuyao>。README 聚焦在线六爻与 AI 解读，和本项目 MVP（先确保时间与排盘事实，不接 AI）范围不同。可以查看界面/数据组织，不要把它的断语逻辑自动纳入项目。
- 已有文档 `docs/references/liuyao-basics-external-sources.md` 和 `docs/references/lesson-06-external-sources.md` 中的链接应先复查，不要重建重复清单。

## 3. 每个来源的审查表

在后续登记中至少记录：

- Source ID
- 标题/作者/仓库所有者
- URL 与具体文件路径
- 类型（课程、代码、历法网站、古籍、现代注释、AI 辅助）
- LICENSE / 版权状态（明确、有限、未查明）
- 最后核查日期
- 与本项目相关的部分
- 可能的偏差、流派/口径差异
- 本项目实际使用的文件/行号/页码/时间戳
- 是否允许复制/修改/公开
- 当前状态：候选、核对中、通过、拒绝/仅供参考

许可证未确认的代码不复制到项目中；版权状态未明的 PDF 不提交到 Public 仓库。可先记录书目信息和合法来源链接。

## 4. 六爻规则的证据等级

每条机器可读规则必须区分：

- **课程明确**：原始转录/课堂笔记可定位，表达与上下文足够明确。
- **外部参考**：来自公开书籍或开源项目；可帮助比较，但不等同于老师讲过。
- **推断/候选**：由 AI、整理者或零散线索提出，必须等待核实。
- **有分歧**：来源之间冲突，保留每种观点、出处和适用口径。
- **已验证为程序规则**：除有证据外，还需要独立计算/人工案例和自动测试通过。

不要把“外部项目里这样写”转化为“课程确认”。尤其要逐项核查硬币映射、六次次序、卦宫、纳甲、六亲基准、世应、旬空以及日月边界。

## 5. 公开与私有仓库流程

1. 原始资料放在私有仓库。
2. 只选与当前实现任务有关的文件读取，避免全量摄入。
3. 生成候选摘要/规则时保留原文件名、页码、时间戳和不确定性。
4. 人工核对后，把自写摘要、来源指针、规则状态、必要的测试数据放入 Public。
5. 公开前检查课程材料版权、PDF 版本、第三方代码许可证、图像及字体许可。
6. 更新任何依赖时检查许可证、版本和维护状态；在项目中记录第三方归属。

私有 GitHub 仍是远程云存储，并不等于本地加密保险库。通过 MFA/Passkey、最小协作者权限、避免在 URL/日志中暴露令牌、保留本地加密备份来降低风险。
