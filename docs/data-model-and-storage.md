# 学习案例与每日卦例：简化数据方案

## 1. 项目里有两类内容

### 课堂学习资料

课堂笔记和老师案例都属于 Learning 项目，继续放在现有的 `liuyao-learning-app` 仓库中，不另建 data repository。

现在的课程笔记已经按课次整理在 `docs/lessons/`，例如：

- 第五课：六亲持世与案例解读，包含公职人员问升职、私企职业经理人问新工作。
- 第十五课：求官、求职、升迁与岗位问题，区分体制外找工作、原单位升迁、询问某单位/公司等问法。
- 第十六课：求财、项目收益与资金链，特别区分事业发展、项目能否落地和实际能否盈利。
- 第十七课：求学、考试、求名与择校/选专业，区分学校、学习、考试结果、功名和专业选择。

**课程笔记继续按课程主题组织；单独的课堂案例则作为案例记录保存。** 案例记录标明来源课次，二者互相引用，不需要复制一套课程目录或分类体系。

### 每日卦例

每日卦例是个人日常数据，与课堂案例分开。当前继续使用 V80 的浏览器本地保存和 JSON 导入/导出。暂时不新建 GitHub 仓库，也不接数据库。等每日记录积累到确实需要云端同步时，再评估 Supabase 等方案。

## 2. HTML 里只保留简单的案例标记

导入课堂案例时，HTML 将它标记为「课堂案例」。随后只需要：

1. **Category**：选择案例分类，例如「求学」或「求工作」。
2. **Tag / Real Question**：一个可选的文字栏。可以写一个简短 tag，也可以直接写老师案例中当事人真正提出的问题。暂时不拆成多个复杂字段。
3. 案例正文：保留老师原始解说；有卦盘资料时保存卦盘，没有的内容不补造。

`Category` 是你在 HTML 中选择的案例分类，不由课程编号自动决定，也不要求预先建立固定分类树。以后分类选项按实际使用需要调整即可。案例库可按 Category 筛选，并能搜索 Tag / Real Question 中的文字。

`sourceLesson` 只记录案例来自哪一课，例如 5、15、17。它是来源信息，不是 Category。

## 3. 单个课堂案例的数据格式

案例数据保持扁平、易读。建议放在 `materials/class-cases/` 目录；不按 Category 建很多子目录，分类只保存在字段里。

```json
{
  "schemaVersion": 1,
  "recordType": "class-case",
  "id": "lesson-15-case-001",
  "sourceLesson": 15,
  "category": "求工作",
  "tagOrRealQuestion": "去这家公司工作怎么样？",
  "casting": null,
  "teacherAnalysis": "老师的原始案例解说"
}
```

字段说明：

| 字段 | 用途 |
|---|---|
| `recordType` | 固定为 `class-case`，表示这是课堂案例 |
| `id` | 案例唯一标识 |
| `sourceLesson` | 来源课次；未知时留空 |
| `category` | 由 HTML 中的 Category 选择 |
| `tagOrRealQuestion` | 可选；写 tag 或真实问事原文 |
| `casting` | 可选的卦盘/起卦快照；原资料没有的部分不补造 |
| `teacherAnalysis` | 老师对这个案例的原始解说，尽量按原文保留 |

这里不额外要求用户填写独立的标题、多个标签数组、学习者笔记、复杂来源类型或分类目录。若课程资料里本身就有标题或完整盘面，可以放入正文/卦盘快照；不是导入的前置条件。

## 4. 与现有课程笔记如何衔接

- `docs/lessons/lesson-XX-notes-v0.1.md` 继续保存每堂课的主题、知识点、课堂口径、待核实事项及学习 App 实施建议。
- `materials/class-cases/` 保存从课程中单独整理出来的案例。
- 案例用 `sourceLesson` 指回课程笔记；课程笔记可以链接到对应案例。
- 不要把笔记中提到但缺少完整卦盘/解说的讨论，自动伪造成完整案例。可以只在课程笔记里保留为「案例线索」。
- 老师原话、老师结论、整理者归纳和不确定之处要区分；课程笔记里已有的待核实说明不要在案例导入时丢掉。

## 5. 每日卦例：暂时维持现状

- V80 的每日记录继续使用浏览器本地存储。
- 每条记录保留起卦日期、卦盘快照和一个 `dailyMemo` 自由记录栏。
- JSON 导入/导出继续用于备份和迁移。
- 每日卦例不进入 Public Learning 仓库，也不与老师课堂案例混在同一个列表。
- 未来若迁移 Supabase，再单独设计数据库表、身份验证和访问权限；现在不提前增加后端。

## 6. 实施顺序

1. 先按上述最小字段确定课堂案例导入界面：课堂案例标记、Category 下拉框、Tag / Real Question 文字栏。
2. 建立 `materials/class-cases/` 案例目录，并从现有课程笔记中挑选真正有材料支撑的案例逐条整理。
3. 案例列表按 Category 筛选，并支持搜索 Tag / Real Question。
4. 每日卦例继续沿用 V80；本阶段不改它的数据存储方式。
