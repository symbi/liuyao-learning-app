# 项目背景与范围

## 1. 项目是什么

这是一个以六爻课程学习为基础的网页项目。学习者可以输入六次摇卦结果，查看本卦、动爻、变卦以及后续排盘步骤。重点是**把规则讲清楚、让结果可核对**，而不是仅输出结论。

## 2. 使用场景

- 学完课程后整理知识点与术语。
- 通过输入摇卦结果练习排卦。
- 回看每个计算步骤使用了什么规则、依据来自哪里。
- 用课程案例测试规则是否实现正确。
- 后续逐步加入练习题和案例复盘。

## 3. 术语约定

- **摇卦 / 摇盘**：用三枚硬币连续摇六次，记录每次结果。
- **排卦 / 排盘**：根据六次结果计算并展示卦象与相关信息。
- **初爻到上爻**：六次输入在界面和数据中必须明确其顺序。
- **本卦、变卦、动爻**：作为首个 MVP 的核心展示内容。

如果课程资料对术语有更具体的定义，应以课程资料为准，并更新本文件。

## 4. 仓库与资料组织

计划把资料分成两层：

- **Public：liuyao-learning-app** — 应用代码、开发文档、整理好的课程摘要、术语表、规则索引、已核对案例、个人整理的 PDF / 其他仓库总结，以及适合公开分享的参考链接。
- **Private：建议另建 liuyao-learning-raw** — 从 Google Drive 导出的原始文件、未整理的课程转录、原始 PDF、重复文件、待分类资料和需要保留原貌的备份。

整理流程是：原始资料先进入 Private raw 仓库或本地原始目录；AI 协助整理后，把经过检查的摘要、规则、术语和案例写入 Public 知识库，并保留来源说明。Public 仓库不能视为私人备份；改成 Private 也不能保证撤回已经被克隆或缓存的内容。

## 6. 设计原则

1. 规则应当有稳定的 ID、明确的输入和输出。
2. 每个排盘结果都应尽可能追溯到规则和来源。
3. 不确定的内容必须显示为待核实，而不是由程序默默猜测。
4. 课程讲解、外部资料、模型推断分别标记。
5. 计算逻辑与网页展示分离。
6. 先实现最小闭环，再逐步增加复杂规则。
